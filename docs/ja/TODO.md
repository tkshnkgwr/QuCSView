## 🎯 ロードマップ概要

QuCSView は **v1.0.0 (正式版)** のリリースにより、500MB超の大規模CSV/TSVファイルに対する「ゼロ型破壊」「高速プレビュー」「インプレース編集」「文字コード相互変換」「ファイル分割」「GitHub Actions CI/CD」を達成しました。

今後の開発では、Excelライクな快適操作性（矩形貼り付け、置換、自動幅調整）と、大容量データ特有の品質向上機能（簡易統計、重複検出、複数ファイル結合）を重点的に推進します。

## 🛠️ 詳細仕様・実装提案一覧

### 1. 優先度：高 (High Priority) — 即時生産性向上 (実装完了 ✅)

#### ✅ 1.1 2次元仮想スクロール（カラム仮想化 / Horizontal Virtualization）
- **概要**: 可視列（10〜15列）のみをDOMにマウントし、200列超の多列CSVでもDOM要素数を96.6%削減。セルクリック・選択ラグを1,000msから2msへ高速化。
- **実装**: `renderStartCol` 〜 `renderEndCol` の絶対座標配置、広域チャンク先読み（2,000行単位 / 10万行保持）。

#### ✅ 1.2 ドラッグ＆ドロップ（D&D）の完全強化＆視覚的オーバーレイ
- **概要**: エクスプローラーからのファイルドラッグ時に画面全体へ半透明のドロップオーバーレイを表示し、テーブル表示中であっても即座にファイル切り替え可能。
- **実装**: Tauri v2 ネイティブファイルドロップとWeb標準イベントの完全両立。

#### ✅ 1.3 選択範囲TSVコピーの確実化＆0ms即時生成
- **概要**: 画面表示セルはローカルメモリキャッシュから0msでTSV即時生成。WebView2のフォーカス喪失時も `document.execCommand('copy')` に自動フォールバック。TSVセルエスケープ完全準拠。

---

### 2. 優先度：中 (Medium Priority) — データ分析・品質向上（今後の実装計画）

#### 📋 2.1 複数列の複合ソート (Multi-Column Sort)
- **概要**: `Shift + カラムクリック` により、第1キー（例: カテゴリ 昇順）、第2キー（例: 金額 降順）などの複合ソートを可能にする。
- **実装方針**: ソート条件配列 `SortKey[]` を Rust バックエンドへ渡し、Rayon並列ソートで瞬時にインデックス並べ替え。

#### 📋 2.2 重複行・重複値の検出＆ハイライト (Duplicate Row Detection)
- **概要**: 指定したキー列（または行全体）において、値が重複しているセル・行をアンバー/パープル色でハイライト表示。
- **実装方針**: Rustバックエンド側で `HashSet` を用いて 500MB データでもミリ秒単位で重複インデックスを走査・返却。

#### 📋 2.3 カラムヘッダーのドラッグ＆ドロップ並べ替え (Column Reordering)
- **概要**: カラムヘッダーを左右にドラッグして列の表示順序を直感的に並べ替え。保存時にも列順序の変更を反映。

#### 📋 2.4 複数CSVファイルの高速マージ結合 (Merge CSV Files)
- **概要**: 同一のカラム構造を持つ複数の分割CSV（例: 日別ログファイル等）を一括選択し、ヘッダーを先頭のみ保持して1つの巨大CSVファイルへ超高速ストリーム結合出力。

#### 📋 2.5 2つのCSVファイル間の差分比較 (CSV Diff Viewer)
- **概要**: 編集前後のファイルや2つのCSVを選択し、変更されたセル（黄色）、追加行（緑色）、削除行（赤色）を視覚的にハイライト比較。

#### 📋 2.6 クリップボード貼り付け時のテーブル自動拡張保護 (Auto-Expanding Paste)
- **概要**: クリップボードから貼り付けた複数行・複数列データが既存のテーブル境界（最大行数・最大列数）を超える場合、自動的に必要な行・列を新規拡張してデータを欠落なく反映。
- **実装方針**: `handleBatchCellEdited` にて境界判定を行い、不足行・不足列をバックエンドの `insert_row` / `insert_col` と連携して自動拡張。

#### 📋 2.7 ソート中のセル編集確定時におけるフォーカス追従 (Focus Tracking under Sort)
- **概要**: カラムソート中にその列のセル値を編集して確定した際、値変更によって行が上下にジャンプしても、編集した行・セルにスクロールとアクティブフォーカスが自然に追従するUX。

#### 📋 2.8 一括置換のRustネイティブ高速化 (`batch_replace_cells`)
- **概要**: 「すべて置換」ダイアログ実行時、数千〜数万件の置換処理をフロントエンドのIPCループではなく、Rustバックエンドに `batch_replace_cells` を新設してインメモリで一括アトミック適用。所要時間を数秒から数十ミリ秒へ短縮。

#### 📋 2.9 CSVエクスポート時のクォート囲みポリシー設定 (Quotation Policy)
- **概要**: 保存モーダルにて、RFC準拠の「必要時のみクォート（自動）」に加え、銀行・基幹システム連携で需要の高い「すべてのセルをダブルクォートで囲む（Always Quote）」「文字列のみクォート」を選択可能にする。

#### 📋 2.10 指定行への即時スクロールジャンプダイアログ (`Ctrl + G`)
- **概要**: 100万行規模の大容量データにおいて、行番号入力ダイアログ（`Ctrl + G`）から指定した物理行番号（例: 85,200行目）へ瞬時にスクロールジャンプ。

## 5. Ver.2.0 軽量化・コード監査による改善課題 (Code Audit Backlog)

2026-11-16 の全ソースコード監査で検出された「Rust/Worker 全量二重ロード・再レンダリング波及・不要タイマー・過剰依存・デッドコード」の解消タスク。

### ⚡ メモリ・二重処理・描画パフォーマンス改善
- [ ] **Rust と Web Worker のファイル全量二重ロード解消 (`src/services/tauriBridge.ts`, `src/hooks/useFileOperations.ts`)**:
  Tauri 環境で Rust 側 mmap オープン直後に `file.arrayBuffer()` や `invoke('get_raw_text', { maxLines: null })` で Web Worker にも全量ロードしている二重処理を廃止し、Tauri 実行時は Rust 側へ一本化する。あわせて表表示中の常時 `rawText` 全文生成・保持を止め、テキストモード切替時のみの取得へ改める。
- [ ] **`RawTextView` の仮想化・デバウンスと `StatusBar` 無用ティック廃止 (`RawTextView.tsx`, `StatusBar.tsx`)**:
  `RawTextView` の非仮想化全行 DOM 生成および 1打鍵ごとの全行 IPC 再パースに仮想スクロールとデバウンスを導入する。また `StatusBar` の `"FPS: 60 | 1s Tick"` 用 1秒ごと `setInterval` と常時 `animate-ping` / `animate-pulse` を廃止し、`App.tsx` の `animate-bounce` や無効な `animate-in` クラス、全セル `transition-colors` も整理する。
- [ ] **テーブル再レンダリング波及とアイドル無条件フェッチの解消 (`App.tsx`, `VirtualTable.tsx`, `TableRow.tsx`)**:
  `App.tsx` のステート集中と `VirtualTable` の関数参照再生成（`isCellInRange` / `isRowSelected`）・`editValue` 全行伝播・`scrollTop`/`scrollLeft` 同期 `setState`・`hasHeader` 含む `key` による `React.memo` 形骸化を修正する。また正規表現ハイライト時のセル毎 `new RegExp` ×3 生成をメモ化する。
- [ ] **Rust / Worker エンジン計算・I/O 効率の最適化 (`grid.rs`, `search.rs`, `io.rs`)**:
  チャンク毎の再ソートをキャッシュ化し、`replace_all` をセル単位ではなく行単位デコード処理へ、`save_to_file` を `BufWriter` 経由かつ高速再構築へ改善する。
