# 開発者指示書 (Developer & AI Instructions)

[English](../../docs/en/INSTRUCTIONS.md) | **日本語版**

## 1. 開発原則と鉄の掟

AIコーディングエージェントおよびすべての開発者は、以下の設計原則を厳格に遵守しなければなりません。

### 🚨 破壊的変更の絶対禁止（イタチごっこ防止）
1. **React側に巨大配列を渡すことの禁止**:
   - `open_file` や `get_slice` のIPC通信において、全行データを一度にフロントエンドへ渡してはならない。必ず画面枠内（30〜50行）のスライスのみを転送すること。
2. **Excel型の推論・型キャストの禁止**:
   - パース時に数値を `Number(str)` や `parseFloat` で変換してはならない。常にプレーンな文字列リテラル（`String` / `&str`）として保持すること。
3. **低CPU負荷・低メモリ消費の維持**:
   - アイドル時CPU負荷 `< 0.1%`、ステータスバーのTick更新頻度は「1秒に1回」を基本とし、高頻度な `requestAnimationFrame` や無限ループタイマーを排除すること。
4. **スティッキー行番号列のスタイル維持**:
   - 行番号列の `sticky left-0`、不透過背景色、境界線シャドウの設定を崩さないこと。

## 2. コード修正時のコメント規約

修正時は必ず変更箇所を以下のフォーマットで挟み、変更理由（Why）を明確に日本語で注釈すること。

```typescript
// UPDATE [日付]: [内容の要約] なぜこの変更を行ったかの理由
// 例:
// UPDATE 2026-08-20: [物理行インデックス] 検索絞り込み時にも元CSVの物理行番号を維持して正確に表示するため
```

---

## 3. コミットメッセージ規約 (Conventional Commits)

コミットメッセージは以下の接頭辞を使用してください。

- `feat:` 新機能の追加
- `fix:` バグ修正
- `perf:` パフォーマンス改善（メモリ削減、処理速度向上）
- `docs:` ドキュメントの更新
- `refactor:` リファクタリング（機能変更なし）
- `test:` テストの追加・更新
